# Deploying to Render + Supabase

Two things to know before you start, because both cost hours if you meet them
the hard way:

1. **Render's free plan sleeps after 15 minutes idle** and takes ~50 seconds to
   wake. Meta gives a webhook a few seconds before retrying, so the first
   message after a quiet spell arrives very late or not at all — precisely the
   message a new customer sends. Starter (~$7/month) stays warm. If that is not
   affordable, see [Running on a free tier](#running-on-a-free-tier) below;
   it is workable with one extra piece.

2. **Use Supabase's *pooler* connection string, not the direct one.** Render
   gives each instance a handful of outbound connections; Supabase's direct port
   allows few concurrent clients. The pooler runs in *transaction mode*, which
   breaks asyncpg's prepared-statement cache — the app detects a pooler URL and
   disables that cache automatically (`app/db/session.py`). Without it you get
   `DuplicatePreparedStatementError`, intermittently, only under real traffic.

---

## 1. Supabase

1. [supabase.com](https://supabase.com) → **New project**. Region **Mumbai
   (ap-south-1)** — same continent as Render's Singapore keeps latency sane.
2. Set a strong database password and save it.
3. **Project Settings → Database → Connection string → URI**, and pick the
   **Transaction pooler** entry (port **6543**, host contains `pooler`).
4. Convert it for SQLAlchemy's async driver — change the scheme:

   ```
   postgresql://...        ->  postgresql+asyncpg://...
   ```

   The app upgrades a bare `postgresql://` automatically, but being explicit
   avoids surprise.

   Final shape:
   ```
   postgresql+asyncpg://postgres.abcdefgh:YOUR_PASSWORD@aws-0-ap-south-1.pooler.supabase.com:6543/postgres
   ```

You do **not** need to create tables. The container runs `alembic upgrade head`
on boot.

---

## 2. Render

1. Push this repository to GitHub.
2. Render → **New → Blueprint** → select the repo. It reads `render.yaml`.
3. Render creates the service and prompts for every `sync: false` variable.

### Values to paste in

| Variable | Where it comes from |
|---|---|
| `DATABASE_URL` | The Supabase pooler URI from step 1 |
| `GROQ_API_KEY` | console.groq.com — **generate a fresh one** |
| `WHATSAPP_PHONE_NUMBER_ID` | Meta → WhatsApp → API Setup |
| `WHATSAPP_ACCESS_TOKEN` | The permanent System User token |
| `WHATSAPP_APP_SECRET` | App Settings → Basic — **must be the same app as the token** |
| `WHATSAPP_VERIFY_TOKEN` | Any random string; paste the same one into Meta |
| `WHATSAPP_ALLOWED_NUMBERS` | Your number, plus colleagues for the soft launch |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | The **entire contents** of `service-account.json` |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | From the sheet URL |

`API_KEY` is generated by Render — copy it from the dashboard afterwards, it is
what protects `/leads`.

> **Why the service account goes in a variable, not a file.** Render's
> filesystem is ephemeral and rebuilt on every deploy, so `secrets/` would not
> survive. The loader accepts either a file path or the raw JSON, so paste the
> whole key into `GOOGLE_SERVICE_ACCOUNT_JSON` and leave the file path unset.

## 3. Point Meta at it

Render gives you a permanent URL like `https://iscale-whatsapp-bot.onrender.com`.
No more ngrok, no more re-pointing after every restart.

Meta app → **WhatsApp → Configuration → Webhook → Edit**:

- Callback URL: `https://YOUR-APP.onrender.com/api/v1/webhook`
- Verify token: the same string as `WHATSAPP_VERIFY_TOKEN`
- Click **Manage** and subscribe to the **`messages`** field — saving the URL
  alone delivers nothing. This is the single most common reason a webhook
  "verifies" and then never fires.

---

## 4. Verify the deploy

```bash
# Should return {"status":"ok"}
curl https://YOUR-APP.onrender.com/api/v1/health

# Every dependency, one line each
curl https://YOUR-APP.onrender.com/api/v1/health/ready

# Should be 401 without the key, 200 with it
curl https://YOUR-APP.onrender.com/api/v1/leads
curl -H "X-API-Key: YOUR_KEY" https://YOUR-APP.onrender.com/api/v1/leads
```

In Render's logs after a successful boot you want:

```
Knowledge base loaded          courses=8
Rate limiting active
WhatsApp allowlist active - only ... can reach the bot
Application started
```

If the allowlist line says **OFF**, stop and fix it before messaging anyone.

---

## 5. Soft launch, then live

Do not remove the allowlist on day one.

1. Deploy with 3–5 colleagues in `WHATSAPP_ALLOWED_NUMBERS`.
2. Run for a day. Read the actual conversations in the `messages` table and the
   leads in the sheet.
3. Fix what reads badly. The knowledge base is JSON — no deploy needed for
   content, only a restart.
4. Only then set `WHATSAPP_ALLOWLIST_ENABLED=false`.

Once it is off, every customer messaging that number reaches the bot, and there
is no undo for a conversation already in flight.

## Running on a free tier

Free hosting is viable here, mainly because of one property of this app: the
webhook acknowledges immediately and processes in a background task, and every
message is de-duplicated on its WhatsApp id by a unique index. So when Meta
retries a delivery that timed out during a cold start, the retry is answered and
the duplicate is discarded. A slow start costs latency, never a double reply.

Options, best first. **Free tiers change often — check current terms before
committing.**

### 1. Render free + an external keep-alive  (easiest, stays on Render)

Render free sleeps on *inactivity*, not on a timer. Pinging it keeps it awake.

1. Deploy exactly as above, but set `plan: free` in `render.yaml`.
2. Create a free monitor at [uptimerobot.com](https://uptimerobot.com) (or
   [cron-job.org](https://cron-job.org)):
   - URL: `https://YOUR-APP.onrender.com/api/v1/health`
   - Interval: **5 minutes**

`/api/v1/health` is deliberately cheap — it touches no database and no network,
so pinging it costs nothing.

Watch the instance-hours: Render free allows ~750/month and staying awake all
month uses ~730. One service fits; two do not.

### 2. Koyeb free

One free web service that does not sleep. Deploys the same Dockerfile. Fewer
moving parts than the keep-alive trick if their free tier still suits you.

### 3. Google Cloud Run

Scales to zero, but cold starts are seconds rather than the ~50s of a sleeping
Render instance, and the free allowance (2M requests/month) is far beyond what
this bot will use. Combined with webhook de-duplication, the occasional cold
start is invisible to users.

### 4. Oracle Cloud Always Free

A genuinely always-on VM (ARM, generous RAM) at no cost. Best resources of any
option, and no sleep at all — but you administer a Linux box yourself:
`docker compose up`, TLS, and updates are your job.

### 5. Cloudflare Tunnel from your own machine  (zero-cost, zero-signup)

If a machine in the office is on anyway, this replaces ngrok properly:

```bash
cloudflared tunnel --url http://localhost:8000
```

A named tunnel gives a **stable HTTPS URL that survives restarts** — unlike
ngrok's free URLs, which change every time and force you to re-point Meta. Good
for the soft launch. Not for production: the bot dies with the machine.

### What to avoid

Do **not** try to dodge cold starts by having the bot reply "one moment...".
That doubles your outbound volume and the user still waits.

## Troubleshooting

| Symptom | Cause |
|---|---|
| Deploy succeeds, health check fails | Platform `$PORT` not honoured. The Dockerfile handles this; check nothing overrode the start command. |
| `DuplicatePreparedStatementError` | Pooler URL not detected. Confirm the host contains `pooler` or the port is 6543. |
| Webhook verifies, nothing arrives | The `messages` field is not subscribed. Meta → Configuration → Manage. |
| Every webhook returns 403 | `WHATSAPP_APP_SECRET` belongs to a different app than the token. Run `scripts/preflight.py`. |
| Sends fail with 190 | Token expired. A System User token with expiry *Never* does not. |
| Sends fail with 133010 | The number is not registered on Cloud API (`platform_type` must be `CLOUD_API`). |
| Leads absent from the sheet | The sheet is not shared with the service account's `client_email` as Editor. Run `scripts/check_sheets.py`. |
| First message after a quiet spell is lost | Free plan sleeping. Upgrade to Starter. |

Before any deploy:

```bash
.venv\Scripts\python.exe scripts\preflight.py --production
```

Exit code 0 means safe to ship.
